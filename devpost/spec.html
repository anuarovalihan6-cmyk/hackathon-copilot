01

Как будем открывать

Сначала на твоём компьютере. Новую программу скачивать сейчас не требуется: Node.js уже установлен.

ЗАПУСК ДЕЛАЮ Я

Одна короткая команда

npm start

Она запустит небольшой служебный файл, который отдаёт браузеру страницу приложения. Здесь команда показана как часть будущего плана; выполнять её сейчас не нужно.

ТЫ ВИДИШЬ СТРАНИЦУ

Постоянный адрес

http://127.0.0.1:4173/

Этот адрес ведёт на твой компьютер. Я открою его после запуска. Пока открыта страница и работает локальный запуск, можно пользоваться приложением.

Один адрес + один профиль браузера = то же сохранённое. Если сменить порт, браузер или очистить данные сайта, прежние записи могут быть недоступны. При повторном запуске используем тот же адрес.
02

Три части и их связь

Node.js помогает открыть страницу. Сама подготовка обрабатывается и сохраняется в браузере.

  1. Файлы проекта + Node.jsОткрывают страницу по постоянному адресу на твоём компьютере. Задачи здесь не хранятся.
  2. Страница в браузереHTML — поля и кнопки. CSS — оформление. JavaScript — действия, язык и прогресс.
  3. Память браузера: localStorageСтраница записывает хакатон, задачи, новости и язык, а при следующем открытии читает их обратно.
03

Что происходит при действиях

Можно раскрывать по одному пункту. Внутри — действие, результат и место в будущих файлах.

1. Создаёшь хакатон

Под Build your MVP / Создай свой MVP вводишь название и календарную дату. JavaScript проверяет поля, сохраняет хакатон и показывает рабочую часть на той же странице.

Название и дату можно исправить. Сохранить изменения применяет их, Отмена оставляет прежнее. Задачи и новости остаются на месте.

PRD: Hackathon Setup · файлы: index.html, main.js, model.js, ui.js.

2. Добавляешь и меняешь задачи

Название обязательно, ответственный — по желанию. Пустое имя показывается как Не назначен / Unassigned. Через редактирование можно назначить человека позже.

Есть отметка выполнения, редактирование и удаление. Редактирование названия или имени сохраняет прежнюю отметку выполнения. Ошибка ввода оставляет текст для исправления.

PRD: Tasks and Assignees · файлы: main.js, model.js, ui.js.

3. Сохраняешь новость со ссылкой

Вводишь заголовок и ссылку на сайт. После проверки новость появляется под задачами. Можно изменить или удалить запись; источник открывается в новой вкладке.

Обновления добавляются вручную. По новости ты решаешь, какую задачу создать. Содержимое сайта приложение автоматически не загружает.

PRD: News and Links · файлы: main.js, model.js, ui.js.

4. Видишь изменение прогресса

Одна выполненная задача из двух → 50%. Рядом с полосой всегда видны процент и количество выполнено / всего.

Нет задач → 0%. Все текущие задачи выполнены → 100%. Снятие отметки, добавление или удаление задачи пересчитывает показатель. Целый процент округляется вниз.

PRD: Preparation Progress · расчёт: model.js · показ: ui.js.

5. Меняешь язык во время ввода

Переключатель EN / RU меняет заголовки, подписи, кнопки и сообщения. Текст, который ты уже ввёл, сохраняется. Названия и имена не переводятся автоматически.

Ручной язык запоминается даже до первого хакатона. Если выбора ещё нет, используем RU для основного русского языка браузера, иначе EN.

PRD: Interface Language · словари: i18n.js · формы и фокус: ui.js.

6. Закрываешь и открываешь снова

Завершённые изменения записываются в localStorage. При возвращении по тому же адресу браузер подставляет хакатон, задачи, новости, отметки и язык.

Незаконченный текст в открытом поле сохраняется при смене языка, но его восстановление после закрытия страницы в эту версию не входит.

PRD: Returning to Preparation · сохранение: storage.js · чтение на старте: main.js.

06

Пустые списки и возможные ошибки

Пока нет записей или поле неверно

Пустые списки приглашают добавить первую задачу или новость. Пустой список задач показывает 0%.

Обязательные поля и ссылка проверяются. Понятная подсказка рядом с полем объясняет, что исправить; введённое остаётся.

Браузер не смог сохранить

Покажем сообщение на выбранном языке. Уже введённые данные остаются видны в текущем открытии; следующее изменение может повторить сохранение.

Если сохранённое повреждено, не перезаписываем его автоматически: сообщаем о проблеме и работаем в памяти до закрытия страницы.

Адрес занят или запуск остановлен

Если нужный порт занят, я разберусь с ошибкой запуска. Адрес не меняем автоматически, чужую программу не завершаем.

Для нового открытия страницы локальный запуск должен работать. Задачи после обычного закрытия страницы остаются в памяти браузера.

Что оставляем на будущее

Автоматические новости, совместное редактирование через интернет и автоматическое распределение задач остаются на будущее. Сейчас подготовку ведёт один человек в одном браузере.

Платные инструменты не добавляем. Чат с ИИ внутри приложения в согласованную первую версию не входит; ИИ помогает нам её создать.

07

Как проверю результат

Это будущие проверки приложения. Во время создания буду выполнять их постепенно.

  • Создание, изменение и удаление записей.
  • Процент после отметки и снятия отметки.
  • Повторное открытие: данные и язык на месте.
  • EN / RU во время ввода: текст остаётся.
  • Пустые поля, ссылки и сбои сохранения.
  • Узкий экран, клавиатура и уменьшение движения.
Для Devpost подготовим публичный GitHub с обязательными документами и видео 1–3 минуты. Демонстрацию можно записать с локального запуска. Публикация работающего сайта в интернете пока не планируется. Требования организаторов.

Технический план согласован

Каждая согласованная функция связана с частью приложения и проверкой. Реализация остаётся небольшой: одна страница, встроенное сохранение и локальный запуск. Внешние сервисы для работы приложения не нужны.
