# Hackathon Copilot — Technical Spec

Полный технический план согласован пользователем после просмотра наглядной версии ответом «давай продалжай работай». Этап `4-spec` завершён; следующий этап — порядок работ и реализация в `5-build`. Принятые решения и выведенные из них детали реализации разделены ниже. Наглядная версия — [spec.html](spec.html).

## How This Works, In Plain Language

Основание: `prd.md > The Core Journey` и `prd.md > Features and Behavior`.

Приложение будет работать на одной веб-странице. HTML задаёт её содержимое: заголовки, поля и кнопки. CSS определяет внешний вид и анимации. JavaScript выполняет действия: добавляет задачи, меняет отметки выполнения, пересчитывает прогресс и переключает язык.

Пользователь выбрал эти три технологии. Агент создаёт файлы, пишет код, запускает доступные проверки и исправляет ошибки. Пользователю не требуется самостоятельно собирать приложение из фрагментов кода. Существенные решения обсуждаем по одному, объясняя назначение и ограничения.

Задачи, новости, хакатон и выбранный язык сохраняются во встроенной памяти браузера — `localStorage`. При повторном открытии по тому же адресу браузер читает их обратно. Прогресс вычисляется по текущим задачам: выполнил одну из двух — увидел 50%.

Для запуска на компьютере небольшой служебный файл на уже установленном Node.js отдаёт браузеру страницу и её файлы по постоянному адресу. Этот файл не хранит задачи. Данные подготовки остаются в браузере.

## The Core Journey Through the System

Реализует `prd.md > The Core Journey`.

1. Открытие страницы → JavaScript читает сохранённое → показывает первый экран или существующую подготовку. Ручной выбор языка имеет приоритет; при отсутствии выбора используется русский для основного языка браузера `ru`, иначе английский.
2. Название и дедлайн → проверка обязательных полей и даты → запись хакатона → показ обзора, задач и новостей на той же странице.
3. Название задачи и необязательное имя → проверка → новая задача → обновление списка, счётчика и сохранённого. Имя можно назначить позже.
4. Заголовок и веб-ссылка → проверка → новость под задачами → сохранение. Содержимое источника приложение не загружает.
5. Отметка выполнения или её снятие → обновление задачи → пересчёт прогресса → сохранение. Изменение и удаление записей также сохраняются.
6. Переключение EN / RU → обновление подписей и сообщений → сохранение языка. Пользовательские данные и текст в открытых формах остаются прежними.
7. Повторное открытие → чтение тех же данных → продолжение подготовки.

## Stack

Выбрано пользователем во время `4-spec`: «давай начнем с HTML, CSS и JavaScript».

- **HTML** — структура одной страницы и формы. [Документация](https://developer.mozilla.org/en-US/docs/Learn_web_development/Core/Structuring_content).
- **CSS** — тёмное оформление, расположение элементов и небольшие анимации. [Документация](https://developer.mozilla.org/en-US/docs/Learn_web_development/Core/Styling_basics).
- **JavaScript** — действия пользователя и обновление данных на странице. [Документация](https://developer.mozilla.org/en-US/docs/Learn_web_development/Core/Scripting/What_is_JavaScript).

Подход предложен для небольшой одностраничной версии, чтобы постепенно объяснять устройство приложения. Поведение форм и обновление списков реализуем в коде проекта. В первой версии сторонние библиотеки не требуются: модули JavaScript работают непосредственно в браузере, сборки нет.

- **localStorage** — согласованное сохранение между открытиями. [Документация](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage).
- **Node.js 24.x**, ранее проверенный установленный выпуск — локальная выдача файлов и проверки. Использовать встроенные [HTTP](https://nodejs.org/docs/latest-v24.x/api/http.html) и [test runner](https://nodejs.org/docs/latest-v24.x/api/test.html); дополнительный пакет для них не нужен. Во время реализации сверить команды с установленным выпуском. Обновление Node.js ради этого проекта не требуется.

## Where It Runs and How Someone Tries It

Реализует `prd.md > Returning to Preparation` и границу одного браузера в `scope.md > The POC Boundary`.

Предлагаемая деталь реализации: запускать локально через встроенный HTTP-сервер Node.js. В корне проекта агент выполнит `npm start`, затем откроет **http://127.0.0.1:4173/**. Команда будет определена в `package.json` как `node scripts/serve.cjs`; `npm test` будет запускать `node --test`. Это будущие команды — до `5-build` соответствующие файлы ещё не созданы.

Использовать обычное окно современного Edge или Chrome и один профиль браузера. Адрес, протокол и порт остаются постоянными: `localhost` и `127.0.0.1`, а также разные порты дают разные места хранения. Закрытие страницы не удаляет сохранённое; после перезапуска локального сервера нужно открыть тот же адрес. Для первого экрана после перезапуска требуется работающий локальный сервер; автономная установка приложения в первую версию не входит.

Сервер слушает только `127.0.0.1:4173` и выдаёт только известные файлы приложения из дерева ниже: HTML, CSS и пять модулей `src/`. Профиль, документы, настройки агента, Git и прочие файлы через него не выдаются. Если порт занят, показать понятную ошибку запуска; автоматически менять адрес или завершать чужой процесс нельзя. Устранить конфликт и сохранить адрес.

После первоначальной загрузки проект не использует внешние запросы, ключи или аккаунты для работы функций; внешняя ссылка открывается только по действию пользователя. Дополнительных зависимостей для скачивания не планируется. Интернет потребуется позже для публикации репозитория и видео.

Для заявки нужны публичный репозиторий и видео **1–3 минуты**, показывающее работающий результат; обязательные `scope.md`, `prd.md`, `spec.md` должны попасть в репозиторий. Пользователь выбрал GitHub. Это сверено с [официальной страницей Devpost](https://learn-ai-basics.devpost.com/). Публичная работающая ссылка не указана среди обязательных материалов: демонстрацию можно записать с локального запуска. Публикация приложения в интернете пока не запрошена и не настраивается; к ней можно вернуться в `6-ship`.

Сценарий будущей записи: создать хакатон, добавить новость, создать две задачи, назначить ответственного, отметить одну задачу и показать 50%, сменить язык, перезагрузить страницу и показать сохранённое. Примерные записи для видео вводить явно как демонстрационные; в обычной первой загрузке списки пусты.

Сохранить выбранные тёмный фон, светлый текст, яркие акценты и плавные анимации; интерфейс на английском и русском. Повторный выбор направления не требуется.

Выведенные агентом начальные параметры для реализации, которые проверим на работающей странице:

- Фон `#101416`, панели `#171d20`, приподнятые элементы `#20282b`; основной текст `#edf2ed`, второстепенный `#a9b4b2`. Акцент `#cff56b` с тёмным текстом `#14190d`; ошибки `#ffb4a7`, фокус `#8fc4ff`. Контрольные границы полей `#667570`, декоративные разделители могут быть тише. Проверить реальные пары цветов: обычный текст 4,5:1, крупный текст и необходимые признаки элементов управления 3:1.
- Системный шрифт с кириллицей (`system-ui`, `Segoe UI`, sans-serif), основной размер 16 px и интервал 1,55. Заголовок адаптивный 32–48 px. Шрифты с внешних серверов не загружаются.
- Одна основная колонка до 980 px. Форма сразу под стартовым заголовком. В рабочем состоянии сверху название, дата и прогресс, затем задачи, затем новости. На узком экране поля и действия переносятся; длинные названия не раздвигают страницу. Основные цели нажатия ориентировочно от 44 px.
- CSS-переход кнопки около 140 мс; новая строка — `opacity` и сдвиг до 4 px за 200 мс; полоса прогресса — `transform: scaleX` за 250 мс. Состояние отметки и данные обновляются сразу. При `prefers-reduced-motion: reduce` декоративные перемещения и переходы отключаются. Постоянной анимации нет.
- Подписи полей видны после ввода; ошибки связаны с полями через `aria-describedby`, неверное поле отмечено `aria-invalid`. Для обновлений — короткое сообщение в `aria-live="polite"`. Цвет сопровождается текстом или состоянием элемента; клавиатурный фокус заметен. Клавиатурой доступны формы, отметки и все действия.

## Components

Это логические части небольшой страницы; они не требуют отдельных библиотек или отдельного файла для каждой карточки.

### Application Coordination

`src/main.js` связывает обработчики форм и кнопок с проверками, данными, отображением и сохранением. На старте получает результат чтения из `storage.js`; после успешного действия обновляет данные в памяти, экран и сохранённое. Процент не хранится отдельно. Реализует `prd.md > The Core Journey` и `prd.md > States and Boundaries`.

### Hackathon Setup and Summary

`index.html`, `src/ui.js`, `src/model.js`: первый экран с заголовком и формой, затем обзор названия, дедлайна и прогресса. Название и действительная календарная дата обязательны. Дата хранится строкой `YYYY-MM-DD`, без времени; при показе локализуется без сдвига календарного дня. Прошедшая дата не запрещена PRD. **Edit hackathon** меняет только название и дату, сохраняя списки. **Save changes** применяет проверенную запись, **Cancel** оставляет прежнюю. Реализует `prd.md > Hackathon Setup` и `prd.md > Proposed Defaults for Review > Input and Corrections`.

### Task List and Editing

`src/ui.js`, `src/model.js`: форма названия и необязательного имени, список с нативными checkbox и действиями **Edit/Delete**. Пустое после обрезки пробелов название недопустимо; пустое имя сохраняется как пустая строка и показывается переводимой пометкой **Unassigned**. Редактирование исправляет название/имя, сохраняя отметку; отмена оставляет прежнюю запись. Добавление, удаление, отметка и снятие отметки пересчитывают прогресс. Реализует `prd.md > Tasks and Assignees` и `prd.md > Proposed Defaults for Review > Empty Lists and Progress`.

### News List and Editing

`src/ui.js`, `src/model.js`: форма заголовка и ссылки, список ниже задач с **Edit/Delete**. Заголовок обязателен. Ссылка проверяется через `URL` и должна иметь протокол `http:` или `https:` и имя сайта; произвольные исполняемые схемы не допускаются. При ошибке поля сохраняют введённое. Ссылка открывается в новой вкладке с `rel="noopener noreferrer"`; предварительной загрузки, автоматических новостей и дополнительной заметки нет. Реализует `prd.md > News and Links` и `prd.md > Proposed Defaults for Review > Input and Corrections`.

### Preparation Progress

Чистая функция в `src/model.js` считает выполненные и общее количество текущих задач. При пустом списке результат 0%. Целый процент округляется вниз: `Math.floor(done * 100 / total)`; 100% достигается только после выполнения всех текущих задач. Полоса отражает действительную долю, рядом всегда видны процент и выполнено/всего. `src/ui.js` обновляет доступный `progress`/`role="progressbar"` и видимую полосу. Реализует `prd.md > Preparation Progress` и `prd.md > Proposed Defaults for Review > Empty Lists and Progress`.

### Browser Storage

`src/storage.js` читает и записывает одну запись `hackathon-copilot:v1` через `getItem`/`setItem`. Данные переводятся в строку через JSON; при чтении проверяются версия, типы, поля, действительные даты и ссылки, уникальность идентификаторов. Сохраняются только завершённые действия и выбор языка; незавершённые формы между закрытиями не обещаны PRD. Текст открытых форм остаётся в текущем открытии при смене языка.

Отсутствующая запись означает первый запуск. Ошибка доступа или записи даёт сообщение на выбранном языке, а текущие данные остаются в памяти и на экране; следующее изменение может повторить сохранение. Повреждённая запись или неизвестная версия не перезаписывается автоматически: показать сообщение о невозможности чтения, работать в памяти и отключить запись для этого открытия. Не очищать всё хранилище браузера. Реализует `prd.md > Returning to Preparation`, `prd.md > Interface Language` и `prd.md > Proposed Defaults for Review > Saving and Returning`.

### Language, Forms and Feedback

`src/i18n.js` содержит словари `en`/`ru` для всех заголовков, полей, кнопок, пустых состояний, ошибок и доступных названий. Сохранённый язык имеет приоритет; иначе выбрать RU при `navigator.language`, начинающемся с `ru`, и EN в остальных случаях. Ручной выбор сохраняется даже без хакатона.

`src/ui.js` меняет подписи, сообщения и атрибут `lang`, сохраняя значения открытых форм, режимы редактирования и фокус; при необходимости восстановить позицию курсора. Пользовательский текст не переводится. Текущие черновики форм хранятся отдельно от сохранённых записей. Повторное открытие редактора той же записи не сбрасывает черновик; черновики разных записей могут оставаться до **Save/Cancel**. Неверный ввод показывает подсказку рядом с полем и не очищает его. Списки показывают **No tasks yet** / **No updates yet** и приглашение к добавлению. Пользовательский текст вставляется через `textContent` и значения полей. Реализует `prd.md > Interface Language`, `prd.md > States and Boundaries` и `prd.md > Proposed Defaults for Review`.

## Data Model

Одна запись в браузере; схема ниже — форма данных, не код приложения:

```text
{
  version: 1,
  language: "en" | "ru",
  hackathon: null | { name: string, deadline: "YYYY-MM-DD" },
  tasks: [{ id: string, title: string, assignee: string, completed: boolean }],
  news: [{ id: string, title: string, url: string }]
}
```

Идентификатор создаётся при добавлении записи и не меняется при редактировании. Когда хакатона ещё нет, списки пусты; выбранный язык может уже быть сохранён. На старте чтение создаёт данные в памяти, каждое принятое действие меняет их, затем экран и сохранённую запись. Ответственный — свободное имя, отдельного списка участников нет. Прогресс получается из `tasks`, не из второго сохранённого числа. Для этого объёма единая запись JSON достаточна; согласован один ведущий в одном браузере, конфликтующее редактирование в нескольких вкладках не координируется.

Отдельно в памяти текущего открытия: тексты форм, ошибки, режимы редактирования, фокус и состояние доступности сохранения. При смене языка они сохраняются, при **Cancel** нужный черновик отбрасывается, при закрытии страницы незавершённые черновики могут пропасть.

## External Services and Dependencies

Рабочие функции приложения используют только возможности браузера. Внешних API, базы данных, ключей доступа, модели ИИ и платных сервисов нет; новости вводит человек. Node.js используется для локального запуска и тестов, не получает данные подготовки. ИИ помогает разработать проект через coding agent; чат с ИИ внутри приложения не входит в согласованный MVP. Репозиторий GitHub и видеохостинг относятся к `6-ship`, не к работе интерфейса. Третьесторонний код из референсов не копируем.

## Important Failure Modes

- Пустое поле, неправильная дата или ссылка → переводимая подсказка возле поля; запись не применяется, ввод сохраняется для исправления.
- Недоступное хранилище, ошибка записи или повреждённое сохранённое → поведение из **Browser Storage**; ложное сообщение об успешном сохранении не показывать.
- Занятый локальный порт → ошибка запуска и объяснение агентом; постоянный адрес не меняется молча. Показ в браузере требует работающего сервера.

## Verification Plan

Проверки относятся к будущему приложению и пока не выполнены.

- `npm test`: правила даты и ссылки, необязательное имя, сохранение отметки при редактировании, пересчёт после отметки/снятия/добавления/удаления, 0% для пустого списка и 100% только для полного выполнения. Проверить границы, а не структуру написанного кода.
- `npm test`: запись и повторное чтение всей подготовки и языка, первый запуск, повреждённый JSON, неверная схема/версия и исключения доступа/записи через подставное хранилище. Исходные данные и чужие ключи не должны уничтожаться.
- В браузере: пройти сценарий видео; отдельно **Edit/Delete**, **Save/Cancel**, ошибки и пустые состояния. Перезагрузить, затем закрыть/открыть страницу по тому же адресу и проверить записи и EN/RU. Ручной язык запоминается ещё до создания хакатона.
- Переключить язык во время ввода и редактирования: проверить текст, фокус, подписи, сообщения. Проверить длинные названия, 320/390/768/1280 px, клавиатуру и измеренный контраст; проверить CSS-правило системного уменьшения движения. Увеличение 200% оценить вручную при финальном просмотре: встроенная автоматизация не меняет масштаб по горячей клавише. Это цели проверки, не заявление о полном соответствии WCAG.
- Проверить локальный сервер: файлы приложения доступны, личный профиль и посторонние пути недоступны. Для демо зафиксировать работающее состояние и проверки, подходящие следующему небольшому шагу `5-build`.

## What Was Simplified and Why

Сохраняет `scope.md > The POC Boundary` и `scope.md > Later`: один хакатон, один ведущий подготовки, ручные новости, свободное имя ответственного. Совместное редактирование, автоматические новости и распределение задач остаются на будущее. Согласованный `localStorage` обеспечивает возврат в тот же браузер без отдельного сервиса. Собственный CSS реализует нужные небольшие анимации. Публичная установка сайта пока не нужна для записи демонстрации; репозиторий и видео всё равно обязательны.

## Decisions and Open Issues

### Agreed Decisions

- HTML, CSS и JavaScript — прямой выбор пользователя. Новые функции не добавляем: границы определяют утверждённые scope и PRD.
- Сохранение через `localStorage` принято ответом «да, подходит сохранение в браузере» после объяснения механизма и ограничения одним браузером.
- Полный показанный технический план принят ответом «давай продалжай работай» после приглашения просмотреть его и предложить изменения. Повторное согласование spec не требуется.
- Маленькие шаги и объяснение каждого действия простыми словами — повторное прямое пожелание пользователя.
- Техническую работу пользователь поручил агенту: «сделай все за меня если сможешь». Это относится к созданию файлов, коду, запуску и проверкам; не является просьбой пропустить обсуждение плана.

### Learner Question: What Must I Install or Do Myself?

Пользователь спросил: «мне нужно будет все скачивать и все делать самому?».

Объяснение: основные технические действия выполнит агент доступными инструментами. Git и Node.js ранее проверены в окружении; сейчас устанавливать их повторно не требуется. Если понадобится личное действие в аккаунте пользователя или недоступная агенту операция, объяснить только этот конкретный шаг. Продолжать обучение через небольшие решения, не требуя от пользователя самостоятельно писать код.

### Implementation Details Derived from These Decisions

Реализует `prd.md > Returning to Preparation`, `prd.md > Interface Language` и `prd.md > Proposed Defaults for Review > Saving and Returning`.

Выбор пользователя определяет механизм `localStorage`. Одна запись JSON, модули файлов, фиксированный адрес локального запуска, конкретная палитра и CSS-переходы предложены агентом как детали этого небольшого проекта и приняты при общем согласовании плана. Пользователь не выбирал каждый цвет или имя файла отдельно.

Данные относятся к конкретному адресу приложения и профилю браузера; автоматического переноса между устройствами нет. Очистка данных сайта удаляет сохранённое, а приватный режим не обеспечивает сохранение после закрытия последней приватной вкладки. Во время разработки нужен постоянный локальный адрес; прямое открытие HTML-файла не следует использовать как основу надёжного сохранения. Если запись недоступна, сохранить данные в текущем открытии и показать сообщение согласно PRD.
